| هر کار تمام‌شده | `docs/STATUS.md` (چه شد، با commit؛ چه ماند؛ قدم بعدی) |

## سبک صفحه‌های `docs/dev/`
هر صفحه این ساختار را دارد:
1. عنوان، و یک خط `>` با فصل و **فایل‌های کد مربوط**،
2. **خلاصه** در چند خط،
3. نمودار Mermaid اگر جریانی یا رابطه‌ای هست،
4. جدول‌ها و مراحل با نام واقعی فایل‌ها، توابع و جدول‌ها،
5. «اگر بخواهید…» با لینک به صفحه‌های مرتبط،
6. «اشتباه‌های رایج» اگر دامی هست.

قواعد:
- نام فایل، کد و اصطلاح فنی انگلیسی بماند؛ متن فارسی.
- هر ادعا را با کد بسنجید. اگر مطمئن نیستید، به فایل لینک بدهید و ادعا نکنید.
- فهرست کامل آدرس‌های API را اینجا تکرار نکنید؛ منبع کامل `GET /api/v1/openapi.json` است. فقط
  آدرس‌هایی را بیاورید که برای فهم جریان لازم‌اند.
- صفحهٔ جدید را به فهرست [`docs/dev/README.md`](../README.md) اضافه کنید.
