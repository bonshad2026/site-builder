# مستندات فنی Site Builder

راهنمای توسعه‌دهنده، به فارسی. هدف: با خواندن این صفحه‌ها بدانید هر بخش کجاست، چطور با بقیه
ارتباط دارد و برای یک تغییر کدام فایل‌ها را باید عوض کنید.

> نام فایل‌ها، کد، اصطلاحات فنی و پیام‌های commit انگلیسی می‌مانند. خلاصهٔ کوتاه و انگلیسیِ
> همین مطالب برای agentها در [`AGENTS.md`](../../AGENTS.md) و [`docs/features/`](../features/) است؛
> وقتی چیزی را عوض می‌کنید، هر دو را به‌روز کنید ([قواعد مستندات](07-rules/docs.md)).

> **راحت‌ترین راه خواندن روی سیستم:** روی `docs\dev\index.html` دوبار کلیک کنید تا همهٔ صفحه‌ها با منو و
> جست‌وجو در مرورگر باز شوند. بعد از ویرایش صفحه‌ها، آن را با `npm run docs:html` دوباره بسازید
> ([قواعد مستندات](07-rules/docs.md)).

## سه نکته که همه‌جا به کارتان می‌آید
1. **هر سایت دیتابیس خودش را دارد.** در آدرس‌های API، `:siteId` همان slug سایت است.
2. **اعتبارسنجی فقط در `packages/shared` تعریف می‌شود** و API و وب هر دو از همان schema استفاده می‌کنند.
3. **بعد از هر تغییر کد، کانتینرهای استودیو را rebuild کنید**؛ استودیو کد را از دیسک نمی‌خواند.
